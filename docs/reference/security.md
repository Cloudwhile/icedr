# 安全部署建议

ICEDR 保存账号、文件、分享和审计记录，应按业务数据系统保护。下面是上线前的最低安全基线。

## 网络边界

- 公网只开放反向代理的 `80` 和 `443`。
- ICEDR 上游端口仅绑定回环地址或受保护内网。
- PostgreSQL、Redis、MinIO 服务端口和管理控制台不直接暴露公网。
- 多层代理只信任明确的上游转发头来源。

## HTTPS

- 正式域名强制 HTTPS。
- 证书自动续期并设置到期告警。
- 页面不混用 HTTP 资源。
- OAuth 回调和 Passkey Origin 与真实 HTTPS 地址完全一致。

详细配置见 [HTTPS 配置](/deployment/https)。

## 密钥与凭据

- 使用 `openssl rand -hex 32` 或同等级方式生成 `AUTH_SECURITY_SECRET`。
- 单独生成 `SHARE_VISITOR_HASH_SECRET`，不得与认证密钥复用；两个值都应长期保存并在多实例间保持一致。
- 数据库、对象存储、SMTP 和 OAuth 使用不同的专用凭据。
- `.env` 权限设为 `0600`，不提交版本库。
- 工单、截图和日志中隐藏密码、Secret、验证码、Cookie 和连接串。
- 轮换凭据前准备双凭据过渡或维护窗口。

## 身份认证

- 至少保留两种经过验证、可以独立登录的管理员认证方式。
- OAuth 要求已验证邮箱，并限制允许域名。
- 只对可信 Provider 启用邮箱关联已有账户。
- Passkey 使用正式 HTTPS 域名，管理员至少绑定两个独立设备。
- 恢复码只用于现有登录会话中的敏感操作验证，不用于登录，也不替代备用登录方式。
- 关闭本地登录前在无痕窗口验证替代方式。

## 外链

- 默认使用邮箱验证或登录访问，公开访问只用于低敏感内容。
- 设置合理有效期和下载次数。
- 对验证码、查看和下载启用限流。
- 定期撤销无人负责、长期有效或访问异常的链接。
- 敏感分享通过独立渠道确认收件人身份。

下载次数不能阻止访客取得文件后再次复制，不应替代数据分级和授权管理。

## 存储与数据库

- PostgreSQL 使用专用数据库与最小权限账号。
- S3 / MinIO Bucket 保持私有，服务账号只访问目标 Bucket。
- 本地数据目录只允许运行账号和备份账号访问。
- 磁盘、数据库连接、对象容量和备份失败设置告警。
- 不直接修改数据库来创建工作区、改对象位置或跳过产品权限。

## 备份

- 数据库和文件对象使用同一恢复点。
- 备份位于独立故障域，并进行加密和访问控制。
- 定期执行隔离恢复演练，而不只检查备份任务“成功”。
- 记录备份对应的 ICEDR 版本和配置。

## 更新

- 固定具体版本标签。
- 校验二进制 SHA256。
- Alpha 版本先在恢复副本中验证。
- 数据库迁移前备份，迁移后不直接用旧版本回连。
- 订阅发布信息和证书、磁盘、备份告警。

## 审计与隐私

- 只有管理员可以查看完整审计记录。
- 审计中可能包含账号、IP、文件名和访客身份，应限制导出和保留范围。
- 定期检查登录失败、策略阻止、分享限流、永久删除和配额变更。
- 发生安全事件时先保留日志和故障现场，再轮换凭据和恢复服务。
