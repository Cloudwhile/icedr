# 故障排查

先记录发生时间、ICEDR 版本、部署方式和最近变更，再按现象排查。不要在未备份时反复删除数据目录、重建数据库或切换存储后端。

## 快速矩阵

| 现象 | 常见原因 | 首先检查 | 处理方向 |
| --- | --- | --- | --- |
| 容器立即退出 | 缺少安全密钥、占位变量、目录权限 | 应用日志 | 补齐 `AUTH_SECURITY_SECRET`，修正变量和权限 |
| 页面无法打开 | 端口、防火墙、进程未运行 | 容器或服务状态 | 恢复进程，检查监听与代理上游 |
| `502` / `504` | 代理上游错误或超时 | Nginx / Caddy 日志 | 修正上游地址，增加上传下载超时 |
| 再次进入初始化 | 数据卷未挂载或数据目录变化 | 实际挂载和数据库文件 | 恢复原数据目录，停止重复初始化 |
| 上传返回 `413` | 代理请求体限制 | 代理配置 | 调整 Nginx、CDN 或 WAF 上限 |
| 上传被拒绝 | 名称冲突、配额或容量不足 | 页面错误码、系统状态 | 选择冲突策略，清理空间或调整配额 |
| 文件列表有记录但打不开 | 存储对象缺失或旧后端被移除 | 存储日志与对象键 | 恢复对象或重新接回旧存储 |
| 外链域名错误 | 公开地址仍为旧值 | 外链基础地址变量 | 改为正式 HTTPS 域名并重建实例 |
| 验证码收不到 | SMTP、发件域名、限流 | 邮件测试和投递日志 | 修复 SMTP，等待限流窗口 |
| OAuth 回调失败 | 回调、Issuer、Secret 或 Origin 不一致 | Provider 与管理页面 | 重新复制回调并测试连接 |
| Passkey 不可用 | HTTP、RP ID 或 Origin 错误 | 浏览器地址与 Passkey 设置 | 使用 HTTPS 并统一域名 |
| S3 测试失败 | Endpoint、TLS、凭据或权限 | ICEDR 与对象存储日志 | 修正网络、CA 和 Bucket 权限 |
| PostgreSQL 无法启动 | 连接、权限或迁移失败 | 应用与数据库日志 | 恢复连接，必要时从备份回滚 |
| 频繁出现 `429` | 访问或验证码限流 | 时间、身份、IP 和审计 | 停止重试，评估策略是否过严 |
| 审计没有记录 | 权限、筛选或短暂延迟 | 重置筛选并刷新 | 确认管理员权限和数据库状态 |

## 启动失败

### Docker

```bash
docker ps -a --filter name=icedr
docker logs --tail 200 icedr
docker inspect icedr
```

重点查找：

- `AUTH_SECURITY_SECRET` 缺失或过短。
- 生产环境仍有占位值。
- 数据目录不可写。
- 端口已被占用。
- 数据库迁移失败。

### systemd

```bash
sudo systemctl status icedr
sudo journalctl -u icedr -n 200 --no-pager
```

确认 `EnvironmentFile` 可读、`ExecStart` 路径正确、运行用户能访问数据目录。

## 初始化向导重复出现

立即停止新的初始化操作，然后检查：

1. Docker 是否挂载到原宿主机目录。
2. `ICEDR_DATA_DIR` 是否变化。
3. 当前目录中是否存在原 `icedr.sqlite` 和 `database-source.json`。
4. 目录所有者和权限是否改变。
5. 恢复操作是否解压到了多一层 `data/data`。

不要通过创建新管理员来“修复”，那会在错误数据源中建立另一套状态。

## 上传与下载

### 大文件失败

- Nginx 设置 `client_max_body_size` 和足够超时。
- 检查 CDN、WAF 和负载均衡的独立限制。
- 检查工作区、成员和物理存储配额。
- 检查上传期间临时空间和对象存储分片权限。

### 下载中断

- 检查代理读取和发送超时。
- 检查对象存储连接和预签名地址是否可从浏览器访问。
- 检查分享是否在下载过程中达到有效期或次数上限。
- 对照审计判断下载是否正式开始。

## 登录

### OAuth

1. 确认 Provider 配置已生效。
2. 确认全局 OAuth 开关已启用。
3. 从管理页面重新复制回调地址。
4. 检查 Issuer / Discovery、Client ID 和 Secret。
5. 检查已验证邮箱和允许域名策略。
6. 在无痕窗口重新测试。

### Passkey

1. 确认系统 Passkey 配置完整。
2. 确认全局 Passkey 登录已启用。
3. 确认当前用户实际绑定了 Passkey。
4. 检查 RP ID、Origin、HTTPS 和浏览器系统时间。

系统配置完成不等于用户已经绑定凭据。

## 外链与邮件

验证码无法发送时先在管理员邮件设置中发送测试邮件。测试成功但外链仍失败时，检查允许域名、验证码限流和发件服务延迟。

链接显示不可用时区分：

- `403`：策略或身份不允许。
- `404`：目标不存在。
- `410`：已撤销、过期或次数用尽。
- `429`：请求过于频繁。

## 收集信息

向维护人员提供：

- ICEDR 版本。
- Docker、Compose 或二进制部署方式。
- 发生时间和时区。
- 状态码与业务错误码。
- 脱敏后的应用、代理、数据库或对象存储日志。
- 最近的升级、域名、存储或认证变更。

不要提供密码、Secret、完整 `.env`、Cookie、验证码、私有下载地址或未脱敏数据库连接串。
