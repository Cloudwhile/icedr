# 初始化向导

初始化向导只在新的数据目录中出现，用于确定数据库、首个管理员、认证方式、邮件、文件存储和站点信息。完成初始化前，先确认当前实例使用的是计划中的持久化目录。

::: danger 不要在错误的数据目录中重复初始化
已经投入使用的实例再次出现初始化向导，通常意味着数据卷未挂载、目录权限错误或启动时切换了 `ICEDR_DATA_DIR`。此时应先停止操作并检查数据目录，不要直接创建第二套管理员和数据。
:::

## 1. 数据库

### SQLite

适合评估、单机和低并发环境。数据库文件保存在数据目录内，部署简单，备份时需要同时保护数据库和本地文件对象。

选择 SQLite 时，请确保：

- 数据目录位于持久化磁盘或 Docker volume。
- 同一个数据库文件只由一个 ICEDR 实例写入。
- 备份前会停止写入或停止实例。

### PostgreSQL

适合需要数据库监控、独立备份和更成熟恢复流程的环境。填写主机、端口、数据库名、用户名和密码后，应先完成连接测试再继续。

使用 PostgreSQL 前，先按 [PostgreSQL 配置](/deployment/postgresql) 创建专用数据库和最小权限账号。

## 2. 管理员账号

首个账号拥有管理员权限。请使用长期可控的邮箱，并设置独立强密码。

完成前建议：

- 确认邮箱没有拼写错误。
- 将凭据保存在组织认可的密码管理器中。
- 不与数据库、对象存储或 SMTP 共用密码。
- 初始化后立即配置第二种可用的登录或恢复方式。

## 3. 登录方式

ICEDR 支持本地账号、OAuth / OIDC 和 Passkey。至少保留一种经过验证的登录方式。

### 本地账号

首次部署建议保留，直到 OAuth 或 Passkey 已在真实域名下完成验证。关闭本地登录前，请先在另一个浏览器会话中确认替代方式可用。

### OAuth / OIDC

初始化时可以先关闭，之后由管理员在“系统设置 → OAuth 配置管理”中添加 Provider、测试连接并设为生效。Provider 生效不等于全局 OAuth 登录已经开启，两项都需要确认。

### Passkey

Passkey 需要正确的站点名称、RP ID 和 Origin。除 `localhost` 外，浏览器通常要求 HTTPS。RP ID 应是域名，Origin 必须与浏览器实际访问的协议、域名和端口一致。

系统配置完成、管理员启用登录和用户实际绑定凭据是三个独立状态。仅完成系统配置不会自动为用户绑定 Passkey。

## 4. 邮件

SMTP 用于邮箱验证码、密码重置和系统邮件。可以在初始化时关闭，完成基础部署后再配置。

启用时需要填写：

- SMTP 主机与端口。
- TLS 设置。
- 用户名和密码。
- 发件人名称与邮箱。
- 可选 Reply-To。

保存前发送测试邮件。测试收件箱没有收到邮件时，同时检查垃圾邮件、发件域名策略和 SMTP 服务日志。详细步骤见 [邮件设置](/guide/admin/mail-settings)。

## 5. 文件存储

### 本地存储

默认写入数据目录内的 `local-files`。适合简单部署，但必须连同数据库一起备份。确认宿主机有足够容量，并为运行用户提供读写权限。

### S3 / MinIO

需要 Endpoint、Region、Bucket、Access Key 和 Secret Key。MinIO 通常启用 Path Style。连接成功只代表凭据可用，还应上传、下载和删除一个测试文件完成闭环。

详细配置见 [MinIO / S3 配置](/deployment/minio-s3)。

## 6. 站点信息

设置用户能识别的站点名称和登录页 Logo。公网地址、邮件发件人、OAuth Provider 和 Passkey RP 信息应使用同一套正式域名与品牌名称，减少钓鱼识别和回调配置错误。

## 完成前检查

- 数据目录或 Docker volume 已持久化。
- 管理员邮箱与密码已安全保存。
- 至少一种登录方式已确认可用。
- 启用 SMTP 时，测试邮件已到达。
- 启用对象存储时，连接测试已通过。
- 正式域名与 HTTPS 已计划好。

完成初始化后，按 [快速开始中的验证流程](/guide/getting-started#部署成功验证流程) 验证登录、文件、分享、审计和重启持久化。
