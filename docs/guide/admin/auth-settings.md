# 认证设置

认证设置决定用户可以如何登录。进入“管理面板 → 系统设置 → 平台配置”管理全局登录方式，进入“OAuth 配置管理”管理具体 Provider。

::: danger 始终保留已验证的登录方式
关闭本地登录、停用 OAuth Provider 或删除最后一个 Passkey 前，先在另一个浏览器会话中验证替代方式。不要只依赖当前管理员会话判断配置成功。
:::

## 本地账号

本地账号适合作为初始和应急登录方式。启用 SMTP 后，用户可以使用邮件相关的恢复流程。

关闭本地登录前确认：

- 至少一个 OAuth Provider 已生效，或管理员已绑定可用 Passkey。
- 替代方式在正式 HTTPS 域名下测试通过。
- 管理员还保留了另一种已经验证、能够独立登录的方式。

## OAuth / OIDC

OAuth 配置分为两层：

1. Provider 配置已保存并设为生效。
2. 全局 OAuth 登录开关已开启。

只有两层都满足，登录页才应提供 OAuth 登录。

### 添加 Provider

1. 打开“OAuth 配置管理”。
2. 选择 Google、GitHub、Microsoft、GitLab、自定义 OIDC 或兼容模式。
3. 填写配置名称、Client ID、Secret 和 Issuer / Discovery 信息。
4. 从界面复制只读回调地址，原样填入身份提供方。
5. 配置 Scopes、邮箱验证、允许域名和首次登录策略。
6. 执行连接测试。
7. 保存为草稿，或保存并设为生效。

同一种 Provider 可以保存多个配置，但同一时间只允许一个配置生效。

### 账号与邮箱策略

- 建议要求 Provider 返回已验证邮箱。
- 自动创建账号时限制允许的邮箱域名。
- “使用可信邮箱关联现有账户”可能把 OAuth 身份关联到已有本地账号，只对可信 Provider 启用。
- 修改 Client Secret 时先在 Provider 侧创建新 Secret，再更新 ICEDR，减少中断时间。

## Passkey

Passkey 有三个不同状态：

| 状态 | 含义 |
| --- | --- |
| 系统已配置 | RP Name、RP ID 和 Origin 完整有效 |
| 全局已启用 | 管理员允许 Passkey 登录 |
| 用户已绑定 | 当前账号实际注册了至少一个 Passkey |

系统已配置不会自动变成用户已绑定。用户需要在个人设置中选择“添加 Passkey”，完成浏览器或设备验证。

### RP 配置

- RP ID 通常填写正式域名，例如 `drive.example.com`，不要包含协议和路径。
- Origin 填写完整来源，例如 `https://drive.example.com`。
- 除 `localhost` 外应使用 HTTPS。
- 反向代理后的浏览器地址必须与 Origin 完全一致。

### 凭据管理

建议为不同设备的 Passkey 使用可识别名称。删除凭据前确认还有其他登录方式；系统会阻止删除可能导致账号完全失去登录能力的最后凭据。

## 恢复码

恢复码用于当前账号已登录时的敏感操作验证，例如添加或移除 Passkey、重新生成恢复码。每个恢复码只能使用一次。

- 恢复码不会在登录页出现，也不能创建登录会话。
- 恢复码不计入管理员要求的登录方式数量。
- 生成恢复码前仍需使用当前账号已有的认证方式确认身份。
- 如果所有登录方式都不可用，应使用邮件密码恢复或由管理员执行既定的账号恢复流程。

## 修改后验证

1. 保持当前管理员页面打开。
2. 在无痕窗口打开登录页。
3. 分别测试计划保留的登录方式。
4. 确认新账号创建、已有账号关联和邮箱域名限制符合预期。
5. 检查审计日志中的成功与失败事件。
