# 审计记录

审计记录用于回答“谁在什么时间，以什么身份，对哪个资源执行了什么操作，结果如何”。完整审计页面需要管理员权限；普通用户能在相关页面看到自己的操作结果，但不能查看整个站点的活动。

## 打开审计日志

进入“管理面板 → 审计日志”。列表支持按以下条件缩小范围：

- 时间范围。
- 操作用户与身份类型。
- 操作类型。
- 文件、分享、传输或系统等资源类型。
- 成功或失败结果。
- 关键词与 IP 地址。

筛选后仍没有记录时，先重置筛选并刷新。刚发生的事件可能有短暂写入延迟。

## 身份类型

| 身份 | 含义 |
| --- | --- |
| 登录账号 | 通过本地账号、OAuth 或 Passkey 登录的用户 |
| 工作区用户 | 工作区上下文中的操作主体 |
| 访客 | 通过公开链接或邮箱验证访问的外部用户 |
| 系统 | 生命周期清理、配置或后台处理产生的事件 |

邮箱验证访客通常以经过保护的身份信息呈现。不要把审计记录导出到无访问控制的公共位置。

## 常见事件

- 登录、登录失败、认证策略阻止、密码重置和 Passkey 变更。
- 文件上传、覆盖、创建版本、预览、下载、重命名、移动、复制和删除。
- 回收站恢复、永久删除和生命周期清理。
- 外链创建、访问、验证码发送、验证成功、预览、下载、撤销和限流。
- 上传任务创建、完成、失败、暂停或取消。
- 工作区配额和成员配额变更。

## 调查外链访问

1. 使用分享备注、文件名或链接对应对象进行关键词筛选。
2. 把资源类型设为“分享”。
3. 按时间排序，依次查看访问、验证码、验证、预览和下载。
4. 对照身份类型、IP 地址和结果状态判断是否为预期访问。
5. 发现异常时先撤销链接，再调整匿名访问、邮箱域名和限流策略。

## 调查上传或下载失败

- 查找同一用户和相近时间的失败事件。
- 区分配额拒绝、存储失败、权限阻止和传输取消。
- 对照系统状态中的存储容量和服务状态。
- 对象存储问题还应检查 MinIO / S3 日志；数据库问题检查 PostgreSQL 日志。

## 保留与隐私

审计记录可能包含账号、访客身份、IP、文件名和操作时间，属于敏感运维数据。只向有职责的管理员开放，并把数据库备份视为包含审计信息的敏感资产。
