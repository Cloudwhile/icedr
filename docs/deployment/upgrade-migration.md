# 升级迁移

升级会替换应用版本，并可能执行数据库结构迁移。当前 ICEDR 仍处于 Alpha，升级前应阅读每个版本的 Release 说明，并把回滚视为“恢复完整备份”，而不是简单改回旧镜像。

## 升级前

1. 记录当前 ICEDR 版本、部署方式和环境变量。
2. 阅读目标版本的发布说明和已知问题。
3. 校验下载的二进制或镜像标签。
4. 完成数据库、文件对象和配置的同一恢复点备份。
5. 在隔离环境恢复一次备份并试运行目标版本。
6. 安排维护窗口，停止上传和配置变更。

## Docker 升级

```bash
docker pull corecherry/icedr-po:目标版本
docker stop icedr
docker rm icedr
```

使用原数据目录、原 `icedr.env` 和新镜像标签重新执行启动命令。不要重新生成 `AUTH_SECURITY_SECRET`。

启动后查看日志：

```bash
docker logs --tail 200 icedr
```

## Compose 升级

修改 `.env` 中的 `ICEDR_VERSION`：

```bash
docker compose pull
docker compose up -d
docker compose logs --tail 200 icedr
```

保留升级前的 `.env` 和 `compose.yaml` 副本，以便准确重建原环境。

## 二进制升级

1. 停止服务。
2. 保留旧二进制。
3. 校验并安装新二进制。
4. 使用原数据目录和环境文件启动。
5. 检查日志和系统状态。

不要删除 `data/assets` 或 `data/native` 作为常规升级步骤；发布程序会按需要准备运行资源。

## 数据库迁移

应用启动会处理与当前版本配套的数据库迁移。迁移期间：

- 只运行一个新版本实例。
- 不要同时启动旧版本写入同一数据库。
- PostgreSQL 必须有迁移前备份。
- SQLite 必须在实例停止时备份整个数据目录。

从 SQLite 切换到 PostgreSQL 目前只在首次初始化向导中提供受控迁移。已投入使用的实例不要通过手工复制表或直接改环境变量迁移。

## 存储迁移

在管理面板把本地存储切换到 S3 / MinIO，只会改变新上传文件的目标，不会移动既有对象。

完整迁移需要：

1. 复制对象到新后端。
2. 保留原对象键和数据库引用关系。
3. 校验数量、大小和抽样哈希。
4. 在隔离实例验证预览、下载和历史版本。
5. 完成恢复演练后再下线旧存储。

不要直接改写数据库中的对象位置。对象迁移必须保留引用关系，并先在隔离环境完成版本匹配和完整验证。

## 升级后验证

- 系统状态显示目标版本且运行正常。
- 本地、OAuth 和 Passkey 登录方式符合预期。
- 上传、预览、下载和回收站可用。
- 旧文件和历史版本可访问。
- 外链验证、预览、下载和撤销可用。
- SMTP 测试邮件成功。
- 审计日志持续写入。
- 重启实例后仍可正常运行。

## 回滚

如果新版本已执行数据库迁移，不要只把镜像或二进制改回旧版本。正确回滚流程是：

1. 停止新版本。
2. 保存故障现场副本和日志。
3. 恢复升级前数据库。
4. 恢复同一时间点的本地文件或对象存储。
5. 恢复原环境配置和旧版本程序。
6. 完成恢复验收后再恢复流量。
